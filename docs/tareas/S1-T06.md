## Objetivo

Crear el esqueleto real de paquetes que describe `ARQUITECTURA.md`, para que
nadie tenga que inventar dónde va cada archivo.

## Documentos a leer

- `docs/tecnico/ARQUITECTURA.md`
- `docs/tecnico/CONVENCIONES.md`

## Archivos a crear o modificar

```
crear: la estructura completa de paquetes bajo mx.donchambitas.app
crear: mx/donchambitas/app/util/Resultado.kt
crear: mx/donchambitas/app/di/ModuloRepositorios.kt
crear: mx/donchambitas/app/di/ModuloSupabase.kt
```

## Qué hacer

Crea los paquetes tal cual el árbol de `ARQUITECTURA.md`: `di`, `dominio` con
`modelo` y `repositorio`, `datos` con `remoto`, `local`, `falso` y
`repositorio`, `ui` con `tema`, `componentes`, `navegacion` y `pantallas`, y
`util`.

Implementa `Resultado<T>` y `TipoError` exactamente como están definidos en
`ARQUITECTURA.md`.

Deja `ModuloRepositorios` y `ModuloSupabase` creados y vacíos, listos para que
las tareas siguientes solo agreguen enlaces. `ModuloSupabase` es donde vivirá el
cliente de `supabase-kt`, pero **en esta tarea se queda vacío**: se construye en
S2-T07.

Un paquete vacío no sobrevive a git: pon un `.gitkeep` donde haga falta.

## Criterios de aceptación

- [ ] Los paquetes coinciden uno a uno con el árbol de `ARQUITECTURA.md`
- [ ] `Resultado` y `TipoError` compilan y están en `util`
- [ ] Los dos módulos de Hilt existen, compilan y están anotados
- [ ] Ningún archivo de `dominio` importa algo de `android.*`
- [ ] `./gradlew assembleDebug` sigue compilando

## Cómo probarlo

```bash
./gradlew assembleDebug
grep -r "import android" app/src/main/java/mx/donchambitas/app/dominio/
```

El grep no debe devolver nada.

## Fuera de alcance

No se implementa ningún repositorio ni modelo todavía. Solo la estructura.
