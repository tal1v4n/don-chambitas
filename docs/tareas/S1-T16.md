## Objetivo

Dejar la infraestructura de pruebas lista y documentada, para que ninguna tarea
posterior tenga excusa para no probar.


## Qué hacer

`PRUEBAS.md` define qué se prueba y qué no. Se prueban: los ViewModels, la
lógica de dominio y los repositorios falsos. No se prueban: los composables sin
lógica, ni el código generado.

`ReglaCorrutinas` es la regla de JUnit que fija el dispatcher de pruebas, para
que ningún ViewModel se pruebe contra el hilo principal real.

`DatosPrueba` es la fábrica de objetos de ejemplo, con valores por defecto y
parámetros con nombre, para que una prueba solo especifique lo que le importa.

Escribe una prueba de ejemplo de cada tipo, que sirva de plantilla: una unitaria
de ViewModel, una de repositorio falso y una de interfaz sobre un componente.

Configura el reporte de cobertura y anota en `PRUEBAS.md` cómo se genera.

## Criterios de aceptación

- [ ] `./gradlew testDebugUnitTest` pasa
- [ ] `./gradlew connectedDebugAndroidTest` pasa con un dispositivo conectado
- [ ] Existen las tres pruebas de ejemplo y funcionan como plantilla
- [ ] `ReglaCorrutinas` permite probar un ViewModel sin hilo principal
- [ ] `DatosPrueba` cubre las entidades principales
- [ ] `PRUEBAS.md` explica qué se prueba, qué no y cómo generar cobertura

## Cómo probarlo

```bash
./gradlew testDebugUnitTest
./gradlew connectedDebugAndroidTest
```

## Fuera de alcance

Sin integración continua. Sin umbral de cobertura obligatorio.
