## Qué hacer

Una interfaz por repositorio, con los métodos que se deducen de
`CONTRATOS-API.md`. Todos los métodos son `suspend` y devuelven `Resultado<T>`.

`FuenteDatosFalsa` es un singleton con listas mutables en memoria y datos de
ejemplo: 8 trabajadores con perfil y servicios, 5 solicitudes en distintos
estados, 3 conversaciones con mensajes, reseñas repartidas, y los catálogos de
categorías, estados y municipios tomados de `04_datos_semilla.sql`.

Cada implementación falsa mete un retraso de 300 ms para que los estados de
carga se puedan probar de verdad, y ofrece una forma de simular error para
probar `EstadoError`.

`ModuloRepositorios` enlaza las diez interfaces con sus implementaciones falsas.
Ese archivo es el único que cambia el día que cada implementación real entre.

## Criterios de aceptación

- [ ] Las diez interfaces existen en `dominio/repositorio/`
- [ ] Todos los métodos devuelven `Resultado<T>` y son `suspend`
- [ ] Ninguna interfaz de dominio importa nada de `datos` ni de `android.*`
- [ ] Las diez implementaciones falsas existen y devuelven datos coherentes
- [ ] Los datos de ejemplo respetan las restricciones del esquema: no hay
      reseñas de solicitudes abiertas ni postulaciones a solicitudes cerradas
- [ ] Cada falsa aplica el retraso de 300 ms
- [ ] Se puede forzar un error para probar `EstadoError`
- [ ] Cambiar de falsa a real requiere tocar **solo** `ModuloRepositorios.kt`

## Cómo probarlo

Escribe una prueba unitaria por repositorio que pida datos y verifique que
llegan. `./gradlew testDebugUnitTest` debe pasar.
