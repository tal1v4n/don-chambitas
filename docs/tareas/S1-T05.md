## Objetivo

Dejar el repositorio con las protecciones y plantillas que el proceso necesita
para que nadie pueda saltarse el flujo por accidente.

## Documentos a leer

- `docs/proceso/PROCESO.md`
- `docs/tecnico/CONVENCIONES.md`

## Archivos a crear o modificar

```
crear: .github/pull_request_template.md
crear: .github/CODEOWNERS
modificar: .gitignore
```

## Qué hacer

1. Protege `main`: nadie empuja directo, se requiere un pull request con al
   menos una aprobación. Aplica también al líder.
2. `CODEOWNERS` con el usuario del líder como dueño de todo el repositorio.
3. Plantilla de pull request con las secciones de `CONVENCIONES.md`: qué hace,
   criterios de aceptación, cómo probarlo y documentación actualizada.
4. Verifica que `.gitignore` cubra `local.properties`, `*.keystore`, `*.jks`,
   `secretos.properties` y `.env`. **Hoy el de la raíz no cubre los cuatro
   últimos**; el que sí los tiene es el que vino con la documentación. Fusiona
   los dos y deja uno solo.
5. Documenta en `PROCESO.md` el nombre exacto del repositorio y la URL.

## Criterios de aceptación

- [ ] Un `git push` directo a `main` es rechazado por el servidor
- [ ] Al abrir un pull request aparece la plantilla precargada
- [ ] `CODEOWNERS` asigna al líder como revisor automático
- [ ] Ningún archivo con credenciales puede subirse por accidente

## Cómo probarlo

Intenta `git push origin main` desde una rama local con un commit. Debe fallar.
Abre un pull request de prueba y confirma que la plantilla aparece y el líder
queda asignado. Cierra el pull request de prueba sin integrarlo.

## Fuera de alcance

Sin integración continua ni acciones automáticas. No están en el alcance del
MVP.
